# Тест-дизайн бізнес-правила «Продовження видачі книжки»

## 1. Прийняті уточнення до специфікації
1. **Формати книжок та тривалість видачі:**
   - `"ebook"` (електронна книжка) — базовий термін і крок продовження **14 днів**.
   - `"paper"` (паперова книжка) — базовий термін і крок продовження **21 день**.
   - Будь-який інший тип книжки вважається недопустимим (`ValueError`).
2. **Ліміт продовжень:** дозволено `renewals_count` рівним `0` або `1` перед продовженням (після операції стає `1` або `2`). Якщо `renewals_count >= 2` — відмова (`ValueError`). Від'ємне значення `renewals_count < 0` вважається некоректним станом (`ValueError`).
3. **Борг читача та прострочення:**
   - Читач не може продовжити видачу, якщо має активний борг (`has_debt = True`) **або** якщо поточна дата більша за термін повернення (`today > due_date`).
   - У день терміну повернення (`today == due_date`) книжка ще не прострочена, тому продовження дозволено.
4. **Черга на книжку:** продовження дозволено лише коли черга порожня (`has_queue = False`). Якщо в черзі є хоча б 1 читач (`has_queue = True`), продовження заборонено (`ValueError`).
5. **Нагадування про термін повернення:** сервіс надсилає нагадування читачеві лише тоді, коли до терміну повернення залишилося **рівно 2 дні** (`(due_date - today).days == 2`).

## 2. Класи еквівалентності та граничні значення

### 2.1. Параметр `book_format` (формат книжки)
| Клас еквівалентності | Вхідне значення | Очікуваний результат | Межа / коментар |
| :--- | :--- | :--- | :--- |
| Допустимий: електронна | `"ebook"` | Новий термін = `due_date + 14 днів` | Стандартний термін для ebook |
| Допустимий: паперова | `"paper"` | Новий термін = `due_date + 21 день` | Стандартний термін для paper |
| Недопустимий: невідомий тип | `"audio"`, `""` | `ValueError` | Перевірка валідації формату |

### 2.2. Параметр `renewals_count` (кількість уже виконаних продовжень)
| Клас еквівалентності | Вхідне значення | Очікуваний результат | Межа / коментар |
| :--- | :--- | :--- | :--- |
| Недопустимий: від'ємне значення | `-1` | `ValueError` | Нижня межа коректності стану |
| Допустимий: перше продовження | `0` | Успіх (`renewals_count` стає `1`) | Межа: книжку ще не продовжували |
| Допустимий: друге (останнє) продовження | `1` | Успіх (`renewals_count` стає `2`) | Межа: останнє дозволене продовження |
| Недопустимий: ліміт вичерпано | `2` | `ValueError` | Межа: перевищення ліміту (рівно 2) |
| Недопустимий: понад ліміт | `3` | `ValueError` | Типове значення класу відмови |

### 2.3. Параметр `today` відносно `due_date` (своєчасність продовження)
| Клас еквівалентності | Різниця `today - due_date` | Очікуваний результат | Межа / коментар |
| :--- | :--- | :--- | :--- |
| Допустимий: завчасно | `-5 днів` | Успіх, додається 14 або 21 день | Типовий випадок до закінчення терміну |
| Допустимий: в останній день терміну | `0 днів` (`today == due_date`) | Успіх, додається 14 або 21 день | Межа: останній день без прострочення |
| Недопустимий: прострочено на 1 день | `+1 день` (`today > due_date`) | `ValueError` | Межа: перший день прострочення (борг) |

### 2.4. Умова нагадування: днів до терміну `days_left = (due_date - today).days`
| Клас еквівалентності | Значення `days_left` | Очікувана дія `notifier.send` | Межа / коментар |
| :--- | :--- | :--- | :--- |
| Рано для нагадування | `3` | Не викликається (`assert_not_called`) | Межа: за 3 дні до терміну |
| Час нагадування | `2` | Викликається 1 раз (`assert_called_once_with`) | Межа: рівно за 2 дні до терміну |
| Нагадування вже минуло / день терміну | `1`, `0` | Не викликається (`assert_not_called`) | Межа: за 1 день та в день здачі |

## 3. Таблиця рішень для операції продовження видачі (`renew_loan`)

Результат залежить від комбінації 4 логічних умов (при валідному `book_format`):
- **C1:** Ліміт продовжень не вичерпано (`renewals_count < 2`)
- **C2:** Черги на книжку немає (`has_queue == False`)
- **C3:** Читач не має грошового боргу (`has_debt == False`)
- **C4:** Видача не прострочена (`today <= due_date`)

| Умова / Дія | R1 (Успіх) | R2 (Ліміт) | R3 (Черга) | R4 (Борг) | R5 (Прострочення) | R6 (Кілька перешкод) |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **C1: `renewals_count < 2`** | Так | **Ні** | Так | Так | Так | **Ні** |
| **C2: Немає черги (`not has_queue`)** | Так | Так | **Ні** | Так | Так | **Ні** |
| **C3: Немає боргу (`not has_debt`)** | Так | Так | Так | **Ні** | Так | **Ні** |
| **C4: Не прострочено (`today <= due_date`)** | Так | Так | Так | Так | **Ні** | Так |
| **D1: Продовжити термін (+14 / +21 дн.)** | **Так** | Ні | Ні | Ні | Ні | Ні |
| **D2: Збільшити `renewals_count` на 1** | **Так** | Ні | Ні | Ні | Ні | Ні |
| **D3: Викинути `ValueError`** | Ні | **Так** | **Так** | **Так** | **Так** | **Так** |

## 4. Трасування тест-дизайну на майбутні тести
- `test_renew_success_by_format_and_renewals` — перевіряє R1, класи `"ebook"` / `"paper"`, межі `renewals_count` (`0`, `1`) та межі `today` (`-5`, `0`).
- `test_renew_rejected_when_limit_reached` — перевіряє R2 (межа `renewals_count = 2` та `3`).
- `test_renew_rejected_when_queue_exists` — перевіряє R3 (`has_queue = True` через stub черги).
- `test_renew_rejected_when_reader_has_debt` — перевіряє R4 (`has_debt = True`).
- `test_renew_rejected_when_overdue` — перевіряє R5 (межа `today = due_date + 1 день`).
- `test_renew_invalid_inputs_raise` — перевіряє невідомий `book_format` та `renewals_count = -1`.
- `test_reminder_sent_only_two_days_before_due` — перевіряє межі `days_left` (`3`, `2`, `1`, `0`) із використанням `FakeClock` та `Mock` нотифікатора.
